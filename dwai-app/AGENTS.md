# Dungeon World AI — App Agent Guide

Next.js frontend. Read the root [`AGENTS.md`](../AGENTS.md) first for the workflow and shared conventions. The app never implements game rules on its own: it displays what the API computes (see [`docs/app/architecture.md`](../docs/app/architecture.md)).

## Commands

Run from `dwai-app/` with Bun:

| Command                                                 | Does                                             |
| ------------------------------------------------------- | ------------------------------------------------ |
| `bun install`                                           | Install dependencies                             |
| `bun run codegen`                                       | Regenerate `gql/` from the running API's schema  |
| `bun dev`                                               | Dev server at `http://localhost:3000`            |
| `bun run test`                                          | Unit tests (`bun test`, files named `*.test.ts`) |
| `bun run lint` / `bun run typecheck` / `bun run format` | Lint / typecheck / format                        |

## Layout

| Path          | Holds                                                             |
| ------------- | ----------------------------------------------------------------- |
| `app/`        | App Router pages; page-specific components sit next to their page |
| `components/` | Shared UI components                                              |
| `fragments/`  | Shared GraphQL fragments                                          |
| `gql/`        | Generated GraphQL types (never edit)                              |
| `lib/`        | Helpers (Apollo client, small utilities)                          |

## Coding Style

- Alphabetize whenever possible (ignoring times when that may break app logic). Some non-exhaustive examples:
  - imports (after all other import rules have been followed)
  - items in a dependencies array for hooks
  - items in an unordered array (or other set of data)
  - component props
  - CSS classes (it is OK to violate this rule for specificity reasons)
- Do not use default exports unless required to by a framework/library (for example, pages in Next.js)
- React components should use "fat arrow" (=>) function expressions combined with a `FC` annotation
- Props should be explicitly defined as a type with the name being the name of their component + "Props"
- Values passed to props should be memoized where possible (for example: event handlers should be created with `useCallback`)

## GraphQL

- Types in `gql/` are generated by `bun run codegen` from the running API's schema — never hand-edit them. Rerun codegen after any API schema change or any change to a `graphql(...)` document.
- Shared selections live in `fragments/`. Read masked fragment data with `unmaskFragment` (renamed from codegen's default `useFragment`, which is not a hook).

## This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.
